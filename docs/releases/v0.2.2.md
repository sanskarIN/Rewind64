# Rewind64 v0.2.2 — experimental Linux x86-64 prerelease

**Explore execution. Trace every instruction. Understand the past.**

This release adds a **read-only code inspection command** to Rewind64's native Assembly interactive debugger. It remains experimental, forward-only and limited to one explicitly launched tracee on Linux x86-64.

## New interactive command: code / x

While stopped at the initial exec trap, a completed single step, or a verified application signal-delivery stop, run:

```text
rewind64> code
Code word at RIP=0x0000000000401000: 0x...............x
rewind64> x
```

The debugger uses **`PTRACE_GETREGS` to refresh the current RIP**, then reads exactly one native eight-byte word starting at that RIP with Linux `PTRACE_PEEKTEXT`. It displays RIP and the machine word in hexadecimal, without writing to the tracee or changing execution state. **This is not disassembly**, nor a command to inspect arbitrary memory addresses. The hexadecimal word uses the host's little-endian x86-64 representation; do not confuse it with a formatted instruction stream.

### Safe ptrace error detection

The Linux ptrace API returns `-1` on failure, but a successful word read can also return `0xffffffffffffffff`. The new Assembly command clears the caller's `errno` before `PTRACE_PEEKTEXT`; if the returned value equals `-1`, it checks `errno` to distinguish valid all-ones data from an actual error. A failed peek displays an error and returns to the debugger command prompt rather than terminating the session.

A new **pure NASM fixture** (`tests/fixtures/all_ones.asm`) places eight `0xff` bytes at its executable entry point. The debugger inspects this word *before execution* and exits by the existing safe `quit`/reap path. No attempt is made to execute invalid fixture bytes.

## Regression tests

The Python-free Bash suite now includes **92 black-box tests**, six more than v0.2.1. New checks validate RIP inspection on entry, after stepping, in compact mode, alongside `regs`, at a pending SIGILL stop, and for a legitimate all-ones word. Native NASM builds and integration tests run on Ubuntu 22.04 and Ubuntu 24.04 in GitHub Actions.

### Basic usage

```sh
./rewind64 --version
./rewind64 run --interactive /path/to/your/authorized/program
./rewind64 run --interactive --changes-only /path/to/your/authorized/program
```

The existing `step/s`, `regs/r`, `status/i`, `continue/c`, `help`, and `quit/q` commands remain unchanged.

## Boundaries

- Linux x86-64 + glibc + ptrace permissions only.
- One launched tracee; no attach, fork/thread following, breakpoints, arbitrary-address memory browsing, symbolic inspection, disassembly, Windows/macOS binary or deterministic replay.
- No trace recording, reverse stepping or historical execution capabilities.
- The debugger is **not a sandbox**. Traced programs inherit the invoking user's permissions. Use only on programs you own or have explicit permission to debug.
