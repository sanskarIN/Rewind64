# Rewind64 v0.1.2 — Linux x86-64 experimental prerelease

**Explore execution. Trace every instruction. Understand the past.**

This experimental prerelease expands register inspection and execution-step diagnostics. It remains a **single-process, forward-only Linux x86-64 debugger prototype**, not a stable debugger or deterministic replay engine.

## Changes since v0.1.1

- Introduces a dedicated NASM register-printing module, `src/registers/x86_64.asm`, for maintainable architecture-specific formatting.
- Shows the complete set of **16 general-purpose x86-64 registers**: RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP, R8–R15, plus RIP, RFLAGS and FS/GS base addresses.
- Reports `Steps completed: actual / requested` after target exit or signal termination, so early exits are not mistaken for completed steps.
- Adds a deterministic Assembly fixture that changes RAX, RBX, R12, and R13; regression tests check their expected values after stepping.
- Expands Python-free build/test CI to Ubuntu 22.04 and Ubuntu 24.04. Bash orchestrates native Assembly fixture tests; **there are no Python build or runtime dependencies**.

## Supported commands

```sh
./rewind64 --help
./rewind64 --version
./rewind64 run /path/to/authorized/program
./rewind64 run --steps 4 /path/to/authorized/program arg1
```

The `--steps` option accepts decimal integers 1–64. This is forward stepping; it does not rewind history.

## Platform / verification

- Native NASM and libc/glibc ABI implementation.
- Tested on Linux x86-64 GitHub Actions runners during release preparation.
- Archive: `rewind64-v0.1.2-linux-x86_64.tar.gz`; checksum: `SHA256SUMS.txt`.
- Test runner: `bash tests/integration/test_cli.sh`, invoked by `make test`.

## Limitations and safety

- No Windows/macOS/ARM64 debugger backend, attach, breakpoints, memory browsing, trace recording, historical stepping, or deterministic replay.
- Does not follow multiple processes/threads and does not validate every possible ptrace event or signal behavior.
- The executable uses system library calls from Assembly and requires normal Linux tracing permissions.
- Debug only programs you own or have explicit authorization to inspect; the target program executes with inherited user permissions.
- No production stability guarantee; the main project license remains Boost Software License 1.0.
