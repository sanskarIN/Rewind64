# Rewind64 v0.2.0 — Linux x86-64 experimental prerelease

**Explore execution. Trace every instruction. Understand the past.**

This release introduces a minimal **interactive Assembly debugger session** for one explicitly launched, authorized Linux x86-64 target. It is an experimental foundation, not a full-featured debugger and **does not** implement trace recording, reverse stepping, deterministic replay, thread tracking, memory reading or breakpoints.

## Interactive execution

```sh
./rewind64 run --interactive /path/to/authorized/program arg1
./rewind64 run --interactive --changes-only /path/to/authorized/program
```

At the initial post-exec ptrace stop, the debugger captures and prints the CPU state and displays `rewind64> `. The following text commands are supported:

| Command | Alias | Behavior |
| --- | --- | --- |
| `step` | `s` | Execute one instruction with Linux `PTRACE_SINGLESTEP` and print CPU register deltas. Repeats are permitted. |
| `regs` | `r` | Read and print the full current Linux x86-64 register snapshot, even when `--changes-only` is selected. |
| `continue` | `c` | Resume the target to exit, continuing to forward application signals and log ptrace exec/exit events. |
| `help` | — | Redisplay session commands. |
| `quit` | `q` | Terminate the launched tracee, drain ptrace stops and attempt to reap it; the session returns success after normal user-initiated shutdown. |
| stdin EOF | — | Treat as `quit` rather than leaving a suspended tracee. |

The command loop runs in **NASM Assembly** using libc `fgets`, `strcmp` and `fflush`; it reuses the existing ptrace tracing code and CPU register formatter. `--interactive` cannot be combined with `--steps N` or `--observe-only`. Session commands require newline-terminated input. The debugger displays `Interactive steps completed: N` for successfully observed steps.

## Quality and tests

- Python-free Bash integration tests feed command scripts to the real debugger using standard input.
- Coverage includes stepping, complete register inspection, `--changes-only`, `continue` with normal and signal exits, in-process `execve`, unsupported job-control group stops, `quit`/EOF child cleanup, short aliases, invalid input, and conflicting CLI options.
- GitHub Actions runs native NASM Linux builds and tests on Ubuntu 22.04 and 24.04. Release packaging uses a fresh test run and emits `rewind64-v0.2.0-linux-x86_64.tar.gz` with `SHA256SUMS.txt`.

## Important limits

- Experimental **Linux x86-64 only**; Windows/macOS/ARM64 backends are not included.
- A single tracee only. Real-world multithreaded programs, fork following, group-stop continuation, and every kind of ptrace event are not supported.
- The interactive prompt currently appears at initial entry and after successfully recognized step stops. A signal or exec event encountered during stepping may transition to automatic continuation instead of returning to the prompt.
- Commands are deliberately minimal. No breakpoints, symbol resolution, source view, disassembler, memory inspector, process attachment or multi-session management.
- This is **forward-only** execution inspection; not a rewind implementation yet.
- Debugged processes run with the caller's privileges, **not in a sandbox**. Debug only authorized programs.
