# Rewind64 v0.2.13 — experimental Linux x86-64 prerelease

**Explore execution. Trace every instruction. Understand the past.**

This experimental release improves inspection of the debugger's eight-entry validated signal-delivery stop history. It remains a **forward-only, single self-launched Linux x86-64 debugger**, not a reverse-execution or recording tool.

## New: `signals [N]` and `g [N]`

At an interactive stop, enter `signals N` or `g N` to show **only the latest 1–8 retained validated signal-delivery stops**. Plain `signals` / `g` still shows the entire retained ring, oldest first.

```text
rewind64> signals 2
Signal history [6]: signal=10 si_code=0 step=0
Signal history [7]: signal=10 si_code=0 step=0
rewind64> g 1
Signal history [7]: signal=10 si_code=0 step=0
rewind64> events
Lifecycle: ...
```

This is an illustrative wrapped-ring example; actual signals, codes and step counters vary by the traced program.

- Counts are **exactly one decimal digit 1–8**: `0`, `9`, `01`, signs, extra spaces and trailing garbage are rejected without resuming the tracee.
- Counts larger than the **currently retained** history are clamped; initial empty history reports no validated signal stops.
- Retained-history indices are preserved even after the eight-slot circular buffer wraps; filtering does not relabel older records as index zero.
- Commands work both newline-terminated and as a final EOF-terminated line.
- Inspection reads only debugger-local bounded history. It does **not** read target process memory, forward a pending signal, or execute a target instruction.

## Regression coverage and validation

This development branch adds **13** native NASM/Bash black-box cases for empty history, single pending signal, count clamping, ten-event wrapped history, full and filtered views, strict malformed counts, read-only repeated inspections, compact output, and newline-free EOF. Expected suite is **217** cases total. Publication is gated on passing `make clean && make test` and GitHub Actions CI on Ubuntu 22.04 and Ubuntu 24.04.

## Scope, safety, and builds

- Linux x86-64 with NASM, gcc/cc, glibc, GNU make, Bash, and system-permitted ptrace of a program you are authorized to debug.
- No Python used or required. Boost Software License 1.0.
- No Windows/macOS debugger backend, process attach, multi-thread follow, breakpoints, source-level debugging, disassembler, persistent execution recording, replay or historical register/memory restoration.
- The experimental release workflow packages a Linux x86-64 native executable plus `SHA256SUMS.txt` only after the full test suite passes. It does not overwrite existing tags.
