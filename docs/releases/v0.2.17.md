# Rewind64 v0.2.17 — experimental Linux x86-64 prerelease

**Explore execution. Trace every instruction. Understand the past.**

This experimental milestone adds a **bounded, non-invasive instruction-address watch**. It can pause a traced program when its RIP reaches an address within at most **64 confirmed instruction steps**, without changing executable code or installing breakpoints.

## New: `until-rip 0xHEX`

Launch a program you own or are authorized to inspect:

```sh
./rewind64 run --interactive ./your-authorized-program
```

In the interactive session, enter `until-rip 0x401003` (substitute a valid executable address for your own target). Rewind64 first checks the current stopped RIP, then uses native Linux `PTRACE_SINGLESTEP` at most 64 times. When the address is reached it prints the matched address, number of steps consumed and current registers. If the address is not reached within the budget it returns to the prompt with an exhaustion message; it does not silently run forever.

Input must be exactly `until-rip 0x` followed by 1–16 hexadecimal digits and a line ending or EOF. An uppercase `0X` prefix and hex letters A–F are permitted. Invalid signs, whitespace, suffixes, overlong numeric fields and extra arguments are rejected before any instruction is executed.

An intervening real application signal cancels the watch and leaves that signal pending at the normal stopped prompt. When the traced program execs a new image, Rewind64 cancels the stale address watch and refreshes its register/RIP baseline. Normal program termination preserves its actual status. `--changes-only` continues to avoid repeated register tables.

## Scope and security

**This is not a persistent breakpoint engine.** No target executable byte is patched, no INT3 instruction is inserted, no remote process is attached, and the maximum stop distance is 64 verified instruction completions. `--capabilities` truthfully reports `execution.rip_watch=true`, `rip_watch_max_steps=64`, but `limitations.breakpoints=false`. The future bounded software-breakpoint engine is tracked in [Issue #25](https://github.com/sanskarIN/Rewind64/issues/25).

The change is implemented in native x86-64 NASM with **17 new Python-free Bash/native Assembly regression scenarios**, with **276/276 tests passed** on Ubuntu 22.04 and 24.04. The [guarded prerelease workflow](https://github.com/sanskarIN/Rewind64/actions/runs/39928572687) passed both supported Ubuntu suites and repeated testing before publishing the Linux native archive and `SHA256SUMS.txt`.

Experimental Linux x86-64 only, one self-launched target, forward-only execution. No Windows/macOS backend, reverse debugger, persistent recording, replay, multi-thread debugging or stable release claim. Boost Software License 1.0.
