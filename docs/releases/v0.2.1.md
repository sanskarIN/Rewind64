# Rewind64 v0.2.1 — experimental Linux x86-64 prerelease

**Explore execution. Trace every instruction. Understand the past.**

This prerelease hardens the native NASM interactive debugger introduced in v0.2.0. It remains **forward-only** and supports one explicitly launched Linux x86-64 tracee.

## Signal-interruption-aware stepping

When an interactive `step` receives a real signal-delivery stop (for example, SIGILL, SIGSEGV, or application SIGTRAP), Rewind64 now **reports the signal and returns to the command prompt while keeping the tracee stopped**. Previously the debugger immediately switched to automatic continuation, leaving no chance to inspect the stopped state.

- `status` (alias `i`) displays `Session status: pid=… steps=N pending_signal=S`. This reports completed interactive steps and the signal currently waiting for a user action.
- `regs` still reads and prints the current x86-64 register state, including while a signal is pending.
- `continue` forwards the pending signal **once** using `PTRACE_CONT`, then continues monitoring normal ptrace event/signal/exit behavior.
- `step` forwards the pending signal **once** using `PTRACE_SINGLESTEP`; the Linux kernel determines whether the target executes, handles the signal or terminates.
- `quit` or stdin EOF shuts down and attempts to reap the target without forwarding the pending signal. The `Signals forwarded: N` counter now increments only after a successful nonzero-signal ptrace resume request, not when merely observing a pending stop.
- If a synthetic ptrace exec/exit event arrives during an interactive step, the debugger continues through the event using existing event handling; it does not incorrectly retain the interactive stepping flag.

## Try it

```sh
./rewind64 run --interactive --changes-only /path/to/authorized/program
```

Example commands:

```text
rewind64> step
rewind64> status
rewind64> regs
rewind64> continue
```

The existing commands `step/s`, `regs/r`, `continue/c`, `help`, `quit/q` remain supported. Observation-only and bounded stepping modes are unchanged.

## Testing, platform, and package

- All debugger executable code and target regression fixtures remain native **NASM x86-64 Assembly**. Make and Bash orchestrate builds/tests; Python is not used.
- Native integration tests cover pending SIGILL, SIGSEGV, application SIGTRAP, status inspection, continuing with the correct pending signal, stepping with a pending signal, and exiting without signal injection, as well as all earlier process lifecycle regressions.
- GitHub Actions runs on Ubuntu 22.04 and 24.04. The prerelease workflow performs a fresh canonical NASM build and Bash tests, then publishes `rewind64-v0.2.1-linux-x86_64.tar.gz` and `SHA256SUMS.txt`.

## Limitations

Only a **single launched Linux x86-64 tracee** is supported. Interactive command input is a minimal terminal-style loop, not a full TTY/job-control manager. Complex thread/fork events, signal handlers and ptrace edge cases still need broader auditing. No process attach, breakpoint management, memory inspection, symbol/source viewer, recording, historical navigation, reverse execution, deterministic replay, or Windows/macOS/ARM64 backend is implemented.

Traced programs run using the current user's permissions and are not sandboxed. Debug only executables you own or have permission to inspect.
