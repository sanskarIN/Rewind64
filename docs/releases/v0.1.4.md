# Rewind64 v0.1.4 — Experimental Linux x86-64 prerelease

**Explore execution. Trace every instruction. Understand the past.**

v0.1.4 is a **Linux x86-64 experimental prerelease**, not a stable, sandboxed, cross-platform, or reverse-execution debugger.

## Changes since v0.1.3

- Added `run [--steps N] [--changes-only] [--] PROGRAM [ARGS...]`. Both options can be placed in either order before the target; `--` ends option parsing for target names beginning with `--`.
- `--changes-only` shows stop headers and per-instruction **forward-only** changed-register values without printing all 16 general-purpose registers and related CPU fields at every step. The debugger still captures full register snapshots in memory to calculate deltas. Default output remains the full register view.
- Added deterministic errors for duplicate CLI options and missing target arguments.
- Validates the initial `PTRACE_TRACEME` exec stop as `SIGTRAP` before single-stepping, rather than treating every stop type as an expected exec stop.
- Added NASM Assembly fixtures for illegal-opcode (`SIGILL`), divide-by-zero (`SIGFPE`), and target exit status 42.
- Expanded native Linux integration testing to **36 Python-free Bash checks**; CI runs them on Ubuntu 22.04 and Ubuntu 24.04.

## Usage

```sh
./rewind64 --help
./rewind64 --version
./rewind64 run /path/to/authorized/program
./rewind64 run --steps 4 /path/to/authorized/program arg1
./rewind64 run --changes-only --steps 4 /path/to/authorized/program
./rewind64 run --steps 4 --changes-only /path/to/authorized/program
./rewind64 run -- --unusual-program-name
```

`--steps N` supports decimal 1–64, default 1. Flags are only parsed before the target program. Use `--` to terminate option parsing. Output is diagnostic text, not a stable machine-readable format.

## Requirements and packaging

- Linux x86-64 with tracing permissions, NASM, libc/glibc, linker and Make to compile, plus Bash and coreutils for tests; **no Python**.
- Binary package: `rewind64-v0.1.4-linux-x86_64.tar.gz`, accompanied by `SHA256SUMS.txt` for integrity checking.
- The program and CPU snapshot handling are written in Assembly and call operating-system/library functions through glibc.

## Limitations

- Only one explicitly launched tracee; no interactive stepping, attachment, thread/process following, breakpoints, memory browsing, trace recording, historical navigation or deterministic replay.
- No support for Windows, macOS, ARM64 or arbitrary kernel tracing restrictions.
- Fault detection and signaling remain incomplete for sophisticated multi-process, threaded or unusual kernel behaviors; exit codes of target and debugger can overlap.
- Debug only executables you own or are authorized to inspect. Tracees execute with inherited user permissions, **not** in a sandbox.
