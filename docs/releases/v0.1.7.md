# Rewind64 v0.1.7 — Linux x86-64 experimental prerelease

**Explore execution. Trace every instruction. Understand the past.**

This release improves process shutdown and job-control stop classification for a **single explicitly launched tracee**. It is experimental; Rewind64 does not yet offer reverse stepping or deterministic replay.

## What's new since v0.1.6

- Uses `PTRACE_GETSIGINFO` to distinguish ordinary signal-delivery stops from Linux job-control **group stops**, identified by `EINVAL` on that query. The initial experimental tracer cannot correctly honor all group-stop semantics; rather than incorrectly injecting `SIGSTOP` repeatedly or hanging, it reports an unsupported group stop and terminates/reaps the tracee.
- After a detected debugger error, cleanup requests `SIGKILL` and drains ptrace `waitpid` stops until a terminal result. The logic handles a pending synthetic `PTRACE_EVENT_EXIT` stop instead of assuming the first wait reaps the child.
- A bounded cleanup loop prevents unbounded reinjection/stop handling if an unexpected sequence occurs. For pathological conditions, cleanup remains best effort rather than guaranteed.
- Added an **Assembly-only SIGSTOP fixture** and Bash regressions for normal display, `--changes-only`, and stops encountered during bounded single-stepping. Tests verify the tracee is no longer running after cleanup.
- Kept the Python-free NASM implementation, native Assembly fixtures, Linux x86-64 ABI, and Boost Software License 1.0.

## Usage

```sh
./rewind64 --version
./rewind64 run /path/to/authorized/program
./rewind64 run --steps 4 --changes-only /path/to/authorized/program
```

`--steps` continues to accept 1..64 instructions. Rewind64 executes the target program with the invoking user's permissions and does **not** sandbox it. Only inspect executables you own or are authorized to debug.

## Packaging and tests

The GitHub Actions release pipeline runs native NASM builds and Bash tests, then publishes a Linux x86-64 `.tar.gz` and matching SHA-256 checksums. Continuous integration covers Ubuntu 22.04 and 24.04. No Python source code or Python runtime is used in the build/tests.

## Limitations

- Linux x86-64 only; no Windows, macOS, or ARM64 backend.
- Job-control group stops are **detected but not supported for continued debugging**; this prototype shuts down the target rather than claiming full job-control handling.
- One explicitly launched tracee. No thread/fork following, interactive debugger, attach, breakpoints, memory browsing, trace recording, historical navigation, reverse execution, or deterministic replay.
- The limited stop budget and signal cleanup are defensive, not a proof that every pathological tracee can be reaped.
- Exit statuses are human-oriented diagnostics and can overlap debugger error return codes.
